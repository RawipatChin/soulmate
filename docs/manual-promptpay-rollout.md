# เปิดใช้ออเดอร์พร้อมเพย์และตรวจสลิปเอง

ระบบออเดอร์ใหม่ใช้ Authentication, Firestore และ Storage โดยตรง สถานะใหม่คือ `pending_payment` → `awaiting_review` → `paid` หรือ `cancelled` สต็อกของออเดอร์ที่ไม่มีสลิปยังถูกจองเมื่อครบ 24 ชั่วโมงจนกว่าแอดมินจะกดยกเลิก ออเดอร์รุ่นเก่ายังอ่านได้และไม่ได้แปลงสถานะย้อนหลัง

## สถานะชั่วคราว: บันทึกออเดอร์ก่อนชำระเงิน

หน้า checkout ปัจจุบันบันทึกออเดอร์และจองสต็อกใน Firestore โดยไม่ต้องมี `config/payment` ออเดอร์ใหม่มีสถานะ `pending_payment` และ `payment.method = null` หน้าเว็บไม่แสดง QR หรือช่องส่งสลิป และลูกค้าไม่ต้องโอนเงินทันที แอดมินยังยกเลิกและคืนสต็อกได้ แต่ยังอนุมัติออเดอร์ที่ไม่มีสลิปไม่ได้

ข้อมูลสินค้าใน Firestore หลักถูกเตรียมเป็น `inventory/{productId}/options/{optionId}` แล้ว 21 ตัวเลือก จากสินค้า 4 รายการ เมื่อเปลี่ยนราคา/สต็อกผ่านหน้าแอดมิน ระบบจะอัปเดตเอกสารเหล่านี้ด้วย

## ลำดับเปิดใช้พร้อมเพย์ในภายหลัง

1. รันทดสอบ Emulator: `npm run test:orders:emulator` และ `npm run test:orders:browser` รวมทั้ง `npm test`, `npm run lint`, `npm run build` โดยติดตั้ง Firebase CLI และ Java ก่อน
2. Deploy กฎก่อนเปิด checkout: `firebase deploy --only firestore:rules,storage --project soulmate-web-bd695`
3. Super Admin เข้า `/admin/orders` ตั้งเบอร์พร้อมเพย์ ตรวจว่าข้อมูลสต็อกของสินค้าทุกตัวเลือกตรงกับหน้าขาย หากมีสินค้าที่ยังไม่มี option ให้กด **เตรียมสต็อกสินค้าที่มีอยู่** ขั้นตอนนี้รันซ้ำได้และเก็บจำนวนที่จองไว้
4. ตรวจรายการ `inventory/{productId}/options/{base|v_<variantId>}` ว่าสินค้าที่ขายอยู่มีราคาและ `available` ถูกต้อง สินค้าที่ไม่มีเอกสาร option จะสั่งซื้อไม่ได้
5. สร้าง QR ทดสอบด้วยเบอร์ที่ตั้งและยอดรวมตัวอย่าง แล้วสแกนด้วย **แอปธนาคารจริง** ตรวจชื่อผู้รับและจำนวนเงินก่อนรับออเดอร์ ห้ามถือว่าการสแกน QR เป็นหลักฐานรับเงิน
6. ลบ Cloud Functions เดิม `createPendingOrder` และ `reconcileOrderExpirations` ที่ยัง deploy อยู่ด้วย `firebase functions:delete createPendingOrder reconcileOrderExpirations --region us-central1 --project soulmate-web-bd695 --force` โค้ดใหม่ไม่มี Functions exports แล้ว แต่การ deploy เฉพาะเว็บหรือกฎไม่ลบฟังก์ชันที่เคย deploy ไว้
7. เมื่อต้องการเปิดรับชำระเงิน ต้องเปลี่ยนการสร้างออเดอร์ใหม่ให้ใส่เบอร์พร้อมเพย์ที่ตั้งไว้ แล้ว build/deploy เว็บอีกครั้ง ทดสอบออเดอร์ยอดเล็กจริงหนึ่งรายการและให้แอดมินตรวจรายการเงินเข้าก่อนอนุมัติ ออเดอร์ที่บันทึกไว้ก่อนหน้านั้นจะไม่เปลี่ยนวิธีชำระอัตโนมัติ

## การทำงานของแอดมิน

- `รอโอน`: ลูกค้ายังส่งสลิปได้จนก่อนครบ 24 ชั่วโมงตามเวลาเซิร์ฟเวอร์ หลังจากนั้นระบบปฏิเสธสลิปและแสดงว่าเกินกำหนด แอดมินกดยกเลิกเองเพื่อคืนสต็อก
- `รอตรวจสลิป`: เปิดภาพสลิป ตรวจผู้รับ ยอด และ **รายการเงินเข้าบัญชีจริง** ก่อนกดอนุมัติ ถ้าสลิปไม่ผ่านให้กดยกเลิกทันทีและระบุเหตุผล สลิปที่ส่งทันเวลายังอนุมัติได้หลังครบ 24 ชั่วโมง
- การอนุมัติและยกเลิกทำใน transaction ที่ตรวจสถานะเดิม การกดซ้ำจะไม่เพิ่มยอดสมาชิกหรือคืนสต็อกซ้ำ

การอ่านสลิปจำกัดเฉพาะเจ้าของออเดอร์และ Admin/Super Admin ที่ active การอัปโหลดจำกัดไฟล์ JPG, PNG, WebP ไม่เกิน 5 MB
