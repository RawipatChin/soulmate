# Domain docs

This repository uses a single-context domain glossary.

## Before working in the codebase

- Read `CONTEXT.md` at the repository root and use its terms in specs, tickets, code, and tests.
- Read ADRs in `docs/adr/` that concern the area being changed, when they exist.
- If a needed term is missing, note the gap for domain modeling rather than inventing a competing term.
- Surface any proposed change that conflicts with an ADR before implementation.

`CONTEXT.md` and ADRs are created or extended as domain decisions are made; their absence does not block unrelated work.
