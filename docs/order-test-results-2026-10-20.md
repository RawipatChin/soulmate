## ขอบเขต

ทดสอบโค้ดในเครื่องด้วย Firebase Auth, Firestore และ Storage Emulator ภายใต้โปรเจกต์จำลอง `demo-soulmate` ข้อมูลออเดอร์ทั้งหมดอยู่ใน Emulator และถูกลบทิ้งเมื่อหยุดชุดทดสอบ ไม่มีการ deploy หรือเขียนข้อมูลลง Firebase ของร้าน ทดสอบทั้ง service/Rules และการกดหน้าเว็บด้วยสินค้าจำลอง โดยไม่ได้ใช้สินค้าและการตั้งค่าจริงบน production

## ข้อสรุปสำหรับออเดอร์ที่บันทึกไม่ได้

ผลทดสอบสนับสนุนว่าจำนวน **รายการสินค้าต่างกันตั้งแต่ 3 รายการขึ้นไป** ทำให้ Rules ใช้งบการประเมินเกินขีดจำกัด จึงถูกปฏิเสธเป็น `permission-denied` ทั้ง transaction ออเดอร์ 4 สินค้าที่รายงานมาก่อนหน้านี้เข้ากับอาการนี้ การส่งฟรีเพียงอย่างเดียวไม่ทำให้ล้ม: ออเดอร์สินค้า 1 รายการที่ถึงเกณฑ์ส่งฟรีผ่านทั้งสองวิธีส่งและทั้งสองวิธีชำระเงิน

ยังไม่ได้ทดสอบออเดอร์จริงยอด ฿3,090 กับการตั้งค่าปัจจุบันของร้านโดยตรง และยังไม่ได้ตรวจว่ากฎที่ deploy อยู่ตรงกับไฟล์ `firestore.rules` ในเครื่องหรือไม่ จึงไม่ควรถือว่าผล Emulator ยืนยันสาเหตุของ production ได้ 100%

## รายการติดตาม

1. เสร็จแล้ว: ลด expressions ใน Rules และทดสอบออเดอร์ 3–5 รายการด้วย Emulator
2. เสร็จแล้วในโค้ดและ unit test: ลองบันทึกซ้ำเฉพาะเมื่อเลขลำดับเปลี่ยน; ยังต้องยืนยันการกดพร้อมกันผ่าน Checkout บนเบราว์เซอร์
3. เสร็จแล้ว: ปรับ browser smoke test ให้ตรงกับ Checkout ปัจจุบัน และรันผ่านด้วย Emulator

ชุดทดสอบหลัก: `scripts/order-emulator-smoke.mjs`, `functions/src/order-domain.test.ts` และไฟล์ `src/services/*.test.ts` ที่ระบุใน `package.json` ข้อความ `permission-denied` ของกรณีปลอมข้อมูล/ไม่มีสิทธิ์ใน log เป็นผลปฏิเสธที่ชุดทดสอบตั้งใจตรวจ ไม่ใช่ความล้มเหลวของกรณีเหล่านั้น

## ผลหลังแก้ Firestore Rules ในเครื่อง

ปรับการตรวจให้กฎสร้างออเดอร์ยืนยันเครื่องหมายการจองสต็อกของทุกรายการ ส่วนกฎอัปเดตสต็อกตรวจรหัสสินค้า ตัวเลือก ราคา จำนวน และยอดต่อรายการในจุดเดียวกัน การทดสอบ Emulator หลังแก้ผ่านทั้งออเดอร์ 3 และ 5 รายการ รวมถึงกรณีถดถอยที่เพิ่มใหม่ **4 สินค้า ราคา ฿746 + ฿566 + ฿1,079 + ฿699 = ฿3,090 ส่งต่างจังหวัดฟรีและชำระ PromptPay** โดยยืนยันว่าออเดอร์บันทึกและสต็อกทั้ง 4 รายการถูกจอง กฎยังปฏิเสธออเดอร์ปลอมที่ไม่มีการจองสต็อก ราคา/ค่าส่ง/ยอดรวมผิด และวิธีส่งหรือวิธีชำระเงินที่ไม่เปิดใช้งาน

ชุดทดสอบออเดอร์เต็มชุดจบด้วย exit code 0 หลังแก้กฎ แต่กรณีออกเลขออเดอร์สองรายการพร้อมกันยังมีบางรอบที่รายการหนึ่งได้ `permission-denied` ในครั้งแรก ชุดทดสอบลองบันทึกซ้ำหลังเลขออเดอร์ขยับแล้วผ่าน จึงเพิ่มการลองซ้ำสูงสุด 3 ครั้งใน `createPendingOrder` เฉพาะเมื่อคำขอถูกปฏิเสธ **และ** อ่านจากเซิร์ฟเวอร์แล้วพบว่าเลขลำดับขยับจริง Unit tests ยืนยันว่ากรณี Rules ปฏิเสธโดยเลขลำดับไม่เปลี่ยนและข้อผิดพลาดอื่นจะไม่ถูกลองซ้ำ การกด Checkout พร้อมกันหลายหน้าต่างยังไม่ได้ทดสอบบนเบราว์เซอร์

Browser smoke test ผ่านบน Emulator: ผู้เยี่ยมชมและสมาชิกกดจากตะกร้าไป Checkout บันทึก PromptPay และเห็น QR, กรณีตัวเลือกสินค้าล้าสมัยกลับไปเลือกใหม่, แอดมินยกเลิกออเดอร์, รับ COD, สร้างใบปะหน้าทั้งชำระล่วงหน้าและ COD, และบันทึกเลขติดตาม ทดสอบหน้ามือถือที่ 390 × 844 px และหน้าแอดมินที่ 1280 × 900 px ระหว่างทดสอบพบว่าปุ่ม Checkout ในตะกร้าและปุ่มเลือกสินค้าใหม่ใน Checkout ถูกกรอบ iframe/เมนูล่างบัง จึงปรับความสูงกรอบมือถือให้เลื่อนในพื้นที่ที่กดได้ แล้ว browser smoke test ผ่าน

การเปลี่ยนแปลงทั้งหมดอยู่ในเครื่อง ยังไม่ได้ deploy และยังไม่ได้ยืนยันกับข้อมูลหรือกฎที่ใช้อยู่บน production
