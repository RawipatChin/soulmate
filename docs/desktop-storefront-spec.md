# ร่างสเปก: โครงหน้าร้าน SOULMATE สำหรับจอคอมพิวเตอร์

สถานะ: `ready-for-human` — implementation ครบแล้ว รอตรวจรับในเบราว์เซอร์ ครอบคลุมเฉพาะฝั่งผู้ใช้ (User)

แหล่งขอบเขตหลัก: [ภาพ Website Sitemap ที่ผู้ใช้ให้มา](./soulmate-website-sitemap.png) โดยอ่านเฉพาะส่วนหน้าแรก ฝั่งผู้ใช้ ตะกร้า ชำระเงิน และหน้าพิเศษที่ผู้ใช้เข้าถึงได้ ส่วนผู้ดูแลระบบในภาพอยู่นอกขอบเขตนี้

## Problem Statement

หน้าร้าน SOULMATE ปัจจุบันออกแบบสำหรับมือถือเป็นหลัก เมื่อเปิดบน Windows หรือเว็บเบราว์เซอร์จอกว้าง ผู้ใช้ยังไม่มีโครงหน้าที่ใช้พื้นที่ได้เหมาะสมและพาไปยังฟังก์ชันฝั่งผู้ใช้ทั้งหมดใน site map ได้ชัดเจน หน้าแรกยังต้องมีพื้นที่สำหรับผู้ช่วยแนะนำสินค้าแบบ RAG ซึ่งตอบจากข้อเท็จจริงของร้านที่ตรวจสอบแล้ว โดยไม่แย่งพื้นที่ค้นหาและซื้อสินค้า

## Solution

ออกแบบโครงหน้าร้าน responsive สำหรับจอคอมพิวเตอร์ โดยยึดลำดับหน้าและฟังก์ชันฝั่งผู้ใช้จาก site map และรักษาการใช้งานมือถือเดิม โครงร่วมประกอบด้วยแบรนด์ เมนูหลัก ทางเข้าบัญชีและตะกร้า พื้นที่เนื้อหา และส่วนท้ายเว็บ โดยวางช่องค้นหาไว้ในเนื้อหาหน้าแรกและหน้ารายการสินค้า แต่ละกลุ่มหน้าใช้รูปแบบจอกว้างที่เหมาะกับงาน เช่น รายการสินค้าและตัวกรอง รายละเอียดสินค้าสองส่วน ตะกร้ากับสรุปยอด และบัญชีกับเมนูย่อย

ในส่วนแรกของหน้าแรก ให้มีพื้นที่ผู้ช่วยแนะนำสินค้าที่มองเห็นได้ชัด พร้อมพื้นที่พอสำหรับคำถาม คำตอบ และสินค้าแนะนำในอนาคต โดยยังเห็นแบนเนอร์หรือโปรโมชัน การค้นหา และทางเข้าสินค้า เมื่อ RAG ยังไม่เปิดใช้ ให้แสดงสถานะตามจริงและไม่สร้างคำตอบปลอม ข้อกำหนดคำตอบในอนาคตยึดเอกสาร product guidance ของโปรเจกต์: ใช้เฉพาะข้อมูลสินค้าที่ร้านอนุมัติ ตรวจราคาและสต็อกปัจจุบัน ไม่วินิจฉัยโรคหรืออ้างผลการรักษา

ใช้ Impeccable ในขั้นออกแบบจริงเพื่อจัดลำดับข้อมูล รูปแบบ responsive การเข้าถึง และสถานะต่าง ๆ โดยให้สีและอัตลักษณ์จาก Stitch เป็นหลัก: พื้นอุ่นเกือบขาว สีมิ้นต์ เขียวเข้ม และชมพูสำหรับจุดที่ต้องการให้ตัดสินใจซื้อ เว็บ Dr.PONG ที่อ้างถึงใช้เป็นแรงบันดาลใจด้านจังหวะหน้าร้าน เช่น แถบข่าว การค้นหา รายการสินค้า และตะกร้า ไม่คัดลอกภาพ ข้อความ โปรโมชัน หรือคำกล่าวอ้างของแบรนด์นั้น

### ขอบเขตจาก site map และสถานะปัจจุบัน

| กลุ่มหน้าฝั่งผู้ใช้ | ในแอปปัจจุบัน | งานโครงหน้าจอคอมพิวเตอร์ |
| --- | --- | --- |
| หน้าแรก `/` | มี | จัดลำดับแบนเนอร์ ค้นหา สินค้า/หมวดหมู่ คอนเทนต์ และพื้นที่ RAG |
| เกี่ยวกับเรา `/about` | ยังไม่มี route | วางหน้าเรื่องราว วิสัยทัศน์/พันธกิจ ทีมงาน และทางติดต่อ |
| สินค้า `/products` และรายละเอียดสินค้า | มี; route รายละเอียดปัจจุบันใช้ `/products/:slug` แต่ภาพระบุ `/product/:id` | วางตัวกรอง/กริดและรายละเอียดสินค้า พร้อมกำหนด alias หรือ redirect |
| บทความ `/articles` และรายละเอียด | ยังไม่มี route | วางรายการ หมวดหมู่ และหน้าอ่านบทความ |
| ชุมชน `/community` | ยังไม่มี route | วางพื้นที่กระทู้ ประสบการณ์ กิจกรรม และกฎชุมชน |
| ติดต่อเรา `/contact` | ยังไม่มี route | วางแบบฟอร์ม ช่องทางติดต่อ ที่อยู่ และ FAQ |
| บัญชี เข้าสู่ระบบ สมัครสมาชิก โปรไฟล์ คำสั่งซื้อ | มีหน้าหลักส่วนใหญ่; route ปัจจุบันใช้ `/account/profile` และ `/account/orders` | วางเมนูบัญชีและหน้ารายละเอียด พร้อมกำหนด alias หรือ redirect ตามภาพ |
| ที่อยู่ `/addresses` และรายการที่ชื่นชอบ `/wishlist` | ยังไม่มี route | วางหน้าหรือสถานะพร้อมเชื่อมบริการเมื่อข้อมูลพร้อม |
| ตะกร้า `/cart` ชำระเงิน `/checkout` ผลสั่งซื้อ `/order-success` | มี | จัดพื้นที่รายการ/แบบฟอร์มกับสรุปยอดและผลลัพธ์ |
| นโยบาย `/privacy` ข้อกำหนด `/terms` และหน้าพิเศษ | มีหน้า 404 ผ่าน fallback; หน้าอื่นยังไม่มี route | วางหน้าข้อมูลจริงและสถานะ 404, coming soon, maintenance |

ตารางนี้บอกสถานะของ route และโครงหน้าเท่านั้น ไม่ยืนยันว่าทุกฟังก์ชันภายในหน้าที่มี route ทำงานครบแล้ว การลงมือแต่ละหน้าต้องตรวจพฤติกรรมจริงอีกครั้ง

## User Stories

1. ในฐานะผู้เข้าชมบนคอมพิวเตอร์ ฉันต้องการเห็นแบรนด์ เมนู ค้นหา บัญชี และตะกร้าอย่างชัดเจน เพื่อเริ่มใช้งานได้ทันที
2. ในฐานะผู้เข้าชมหน้าแรก ฉันต้องการเห็นแบนเนอร์หรือโปรโมชัน สินค้าแนะนำ หมวดหมู่ บทความหรือคอนเทนต์ เมนูนำทาง และผู้ช่วยถามตอบในลำดับที่เข้าใจง่าย เพื่อเลือกเส้นทางต่อได้
3. ในฐานะผู้ที่ต้องการคำแนะนำสินค้า ฉันต้องการเห็นพื้นที่ถามตอบบนหน้าแรกโดยไม่เสียทางเข้าสินค้า เพื่อเลือกได้ว่าจะถามหรือเลือกดูเอง
4. ในฐานะผู้ที่ต้องการคำแนะนำสินค้า ฉันต้องการทราบชัดเมื่อผู้ช่วยยังใช้งานไม่ได้ เพื่อไม่เข้าใจผิดว่าส่งคำถามสำเร็จแล้ว
5. ในฐานะผู้ที่ใช้ผู้ช่วยในอนาคต ฉันต้องการให้คำตอบอ้างอิงเฉพาะข้อมูลสินค้าที่ตรวจสอบแล้วและแสดงสินค้าที่ซื้อได้จริง เพื่อเชื่อถือเหตุผลประกอบคำแนะนำ
6. ในฐานะผู้เข้าชมหน้าเกี่ยวกับเรา ฉันต้องการอ่านเรื่องราว วิสัยทัศน์ พันธกิจ ทีมงาน และช่องทางติดต่อ เพื่อรู้จักร้านก่อนซื้อ
7. ในฐานะผู้เลือกสินค้า ฉันต้องการเห็นสินค้าทั้งหมด หมวดหมู่ การค้นหา และตัวกรองบนจอกว้าง เพื่อหาสินค้าที่ตรงความต้องการ
8. ในฐานะผู้เลือกสินค้า ฉันต้องการเห็นรูป รายละเอียด รีวิว และสินค้าที่เกี่ยวข้องบนหน้ารายละเอียด เพื่อเปรียบเทียบก่อนตัดสินใจ
9. ในฐานะผู้เลือกสินค้า ฉันต้องการเห็นราคา ตัวเลือก และสต็อกที่ตรงกับสินค้าที่เลือก เพื่อไม่กดซื้อสินค้าที่ไม่มีอยู่
10. ในฐานะผู้อ่านบทความ ฉันต้องการดูรายการ หมวดหมู่ และรายละเอียดบทความ เพื่อค้นหาความรู้ที่สนใจ
11. ในฐานะสมาชิกชุมชน ฉันต้องการเห็นพื้นที่กระทู้ การพูดคุย ประสบการณ์ กิจกรรม และกฎชุมชน เพื่อทราบวิธีมีส่วนร่วม
12. ในฐานะผู้ต้องการติดต่อร้าน ฉันต้องการเห็นแบบฟอร์ม ช่องทางติดต่อ ที่อยู่ และคำถามที่พบบ่อย เพื่อเลือกวิธีติดต่อที่เหมาะสม
13. ในฐานะผู้เข้าชมที่ยังไม่เข้าสู่ระบบ ฉันต้องการไปยังหน้าเข้าสู่ระบบและสมัครสมาชิกได้ง่าย เพื่อใช้สิทธิ์ของบัญชี
14. ในฐานะลูกค้า ฉันต้องการดูและแก้ไขข้อมูลส่วนตัว ที่อยู่ รหัสผ่าน และรูปโปรไฟล์ เพื่อดูแลข้อมูลบัญชี
15. ในฐานะลูกค้า ฉันต้องการดูรายการสั่งซื้อ รายละเอียด และสถานะการจัดส่ง เพื่อทราบความคืบหน้าของคำสั่งซื้อ
16. ในฐานะลูกค้า ฉันต้องการดูที่อยู่และรายการที่ชื่นชอบจากบัญชี เพื่อกลับมาซื้อสินค้าได้สะดวก
17. ในฐานะลูกค้า ฉันต้องการออกจากระบบได้ชัดเจน เพื่อปิดการใช้งานบัญชีบนเครื่องที่ใช้ร่วมกัน
18. ในฐานะผู้ซื้อ ฉันต้องการดูรายการในตะกร้า ปรับจำนวน ลบสินค้า ดูยอดรวม และใช้คูปอง เพื่อทบทวนก่อนชำระเงิน
19. ในฐานะผู้ซื้อ ฉันต้องการกรอกที่อยู่ เลือกวิธีจัดส่งและชำระเงิน ตรวจสรุปคำสั่งซื้อ และยืนยันจากหน้าชำระเงิน เพื่อสั่งซื้อให้ครบขั้นตอน
20. ในฐานะผู้ซื้อที่สั่งซื้อสำเร็จ ฉันต้องการเห็นหน้าแสดงผลสำเร็จและทางไปดูคำสั่งซื้อ เพื่อมั่นใจว่าระบบรับคำสั่งซื้อแล้ว
21. ในฐานะผู้เข้าชม ฉันต้องการเข้าถึงนโยบายความเป็นส่วนตัวและข้อกำหนดการใช้งาน เพื่ออ่านข้อมูลก่อนใช้บริการ
22. ในฐานะผู้เข้าชมที่ไปยังที่อยู่ผิด ฉันต้องการหน้า 404 พร้อมทางกลับ เพื่อไม่ติดอยู่ในหน้าว่าง
23. ในฐานะผู้เข้าชมระหว่างปรับปรุงระบบ ฉันต้องการเห็นหน้า coming soon หรือ maintenance ที่บอกสถานะตามจริง เพื่อทราบว่าจะทำอะไรต่อได้
24. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการลำดับโฟกัสและสถานะโฟกัสที่ชัด เพื่อใช้หน้าร้านโดยไม่ต้องใช้เมาส์
25. ในฐานะผู้ใช้จอแล็ปท็อปหรือหน้าต่างที่ถูกย่อ ฉันต้องการให้โครงหน้าปรับตามความกว้างโดยไม่มีข้อความถูกตัดหรือเลื่อนแนวนอน เพื่อใช้งานต่อได้
26. ในฐานะผู้ใช้มือถือเดิม ฉันต้องการให้เส้นทางซื้อสินค้าเดิมยังทำงานได้ เพื่อไม่ถูกกระทบจากการเพิ่มหน้าจอคอมพิวเตอร์

## Implementation Decisions

- ขอบเขตหน้าฝั่งผู้ใช้จาก site map ได้แก่ หน้าแรก, เกี่ยวกับเรา, สินค้าและรายละเอียด, บทความ, ชุมชน, ติดต่อเรา, บัญชี, ตะกร้า, ชำระเงิน, หน้าสั่งซื้อสำเร็จ และหน้าพิเศษที่ผู้ใช้เข้าถึงได้ ไม่มีงานหน้า Admin ในสเปกนี้
- ใช้ site map เป็นขอบเขตฟังก์ชัน แม้บางหน้าในภาพยังไม่มี route หรือบริการจริงในแอปปัจจุบัน โครงหน้าสำหรับกลุ่มนั้นต้องแยกสถานะว่า “มีอยู่แล้ว” หรือ “ต้องสร้างเพิ่ม” และไม่แสดงฟังก์ชันหลอกว่าใช้งานได้
- สร้างโครงนำทางร่วมของฝั่งผู้ใช้สำหรับจอกว้าง: โลโก้ เมนูหน้าหลัก บัญชี ตะกร้าพร้อมจำนวนสินค้า โดยช่องค้นหาอยู่ในเนื้อหาหน้าร้าน และส่วนท้ายที่รวมข้อมูลช่วยเหลือ/นโยบาย การย่อสู่จอเล็กต้องกลับไปใช้รูปแบบมือถือที่เหมาะสม
- หน้าแรกใช้ส่วนแรกของหน้าจอสำหรับการค้นหา/เลือกซื้อและพื้นที่ product guidance assistant ควบคู่กัน พื้นที่ถามตอบเป็นส่วนประกอบที่พร้อมเชื่อมต่อภายหลัง ไม่บังแบนเนอร์หรือทางเข้ารายการสินค้า
- หน้าสินค้าใช้พื้นที่ตัวกรองกับกริดสินค้าที่ปรับจำนวนคอลัมน์ได้ รายละเอียดสินค้าใช้พื้นที่ภาพกับรายละเอียดและการซื้อที่อ่านพร้อมกันได้ ตะกร้าและชำระเงินแสดงรายการหรือแบบฟอร์มคู่กับสรุปยอดเมื่อความกว้างเพียงพอ
- หน้าเนื้อหา เช่น เกี่ยวกับเรา บทความ ชุมชน และติดต่อเรา ใช้โครงส่วนหัว/ส่วนท้ายร่วม แต่มีลำดับเนื้อหาและสถานะตามหน้าที่ของตน ไม่แปลงทุกหน้าให้เป็นกริดสินค้า
- หน้าบัญชีใช้เมนูย่อยกับเนื้อหาที่อ่านพร้อมกันได้บนจอกว้าง โดยคงการป้องกันเส้นทางสำหรับข้อมูลส่วนตัวและคำสั่งซื้อ
- route ที่ site map และแอปปัจจุบันสะกดต่างกัน เช่น รายละเอียดสินค้า โปรไฟล์ และคำสั่งซื้อ ต้องกำหนด canonical route และพฤติกรรม alias/redirect ก่อนลงมือ เพื่อไม่ทำลายลิงก์ที่มีอยู่
- สี ฟอนต์ โลโก้ ภาพ และระดับความโค้งยึด Stitch SOULMATE ที่มีอยู่ ดึงแนวคิดโครงร้านจากเว็บอ้างอิงเท่านั้น ข้อความโปรโมชัน ราคา สินค้า และ health claim ต้องมาจากข้อมูล SOULMATE ที่ตรวจสอบแล้ว
- องค์ประกอบ RAG ในรุ่นโครงหน้าต้องมีสถานะยังไม่เปิดใช้ที่ซื่อสัตย์ ภายหลังจึงเชื่อมอินพุตคำถาม บทสนทนาชั่วคราว คำตอบที่มีหลักฐาน สินค้าแนะนำ และสถานะกำลังโหลด/ไม่มีผลลัพธ์/ผิดพลาด ตามเอกสาร product guidance เดิม
- โครงหน้าเว็บต้องรองรับภาษาไทย ตัวอักษรวรรณยุกต์ การใช้งานคีย์บอร์ด คอนทราสต์ที่อ่านได้ และการย่อขนาดหน้าต่างโดยไม่ซ่อนปุ่มซื้อหรือสรุปสำคัญ

## Testing Decisions

- จุดตรวจรับหลักอยู่ที่เส้นทางหน้าร้านจริงในเบราว์เซอร์ โดยตรวจพฤติกรรมที่ผู้ใช้เห็นแทนการตรวจชื่อคอมโพเนนต์หรือรายละเอียด CSS
- ตรวจการนำทางจากหน้าแรกไปทุกกลุ่มหน้าฝั่งผู้ใช้ใน site map รวมถึงทางกลับ/404 และระบุหน้าที่ยังไม่มีบริการจริงให้ตรงตามสถานะ
- ตรวจเส้นทางค้นหาสินค้า → รายละเอียดสินค้า → ตะกร้า → ชำระเงิน → ผลสั่งซื้อสำเร็จ โดยใช้ข้อมูลจริงหรือชุดข้อมูลทดสอบที่ระบุชัด
- ตรวจหน้าบัญชีที่ต้องเข้าสู่ระบบ การกลับไปหน้าที่ตั้งใจเปิด และการแสดงคำสั่งซื้อ/โปรไฟล์ตามสิทธิ์
- ตรวจหน้าแรกที่ความกว้างคอมพิวเตอร์ แล็ปท็อป ช่วงเปลี่ยนผ่าน และมือถือ ว่าพื้นที่ RAG ไม่ดันการค้นหา/สินค้าออกจากลำดับสำคัญ และไม่มี overflow
- ตรวจสถานะว่าง กำลังโหลด ข้อผิดพลาด ข้อความไทยยาว สินค้าจำนวนมาก และการใช้งานคีย์บอร์ด
- รุ่นนี้ตรวจสถานะ RAG ที่ยังไม่เปิดใช้ เมื่อเชื่อมระบบจริงค่อยเพิ่มกรณีคำแนะนำจากข้อมูลอนุมัติ คำถามเกี่ยวกับอาการ ข้อมูลขาดหาย สินค้าไม่ตรง และสต็อก/ราคาปัจจุบัน
- ใน checkout นี้ยังไม่พบชุดทดสอบ UI หน้าร้านที่ commit ไว้ การทำงานรุ่นแรกจึงควรตั้งการทดสอบผ่านเส้นทางจริงขนาดเล็ก ณ จุดตรวจรับเดียวกัน

## Out of Scope

- หน้าและฟังก์ชันฝั่งผู้ดูแลระบบทั้งหมด แม้อยู่ในภาพ site map เดียวกัน
- การสร้าง backend ของบทความ ชุมชน ติดต่อเรา หรือหน้าบัญชีที่ยังไม่มีบริการจริง งานนี้กำหนดโครงหน้าฝั่งผู้ใช้และสถานะที่ซื่อสัตย์สำหรับช่องว่างเหล่านั้น
- การสร้าง RAG service, model call, retrieval pipeline, การอนุมัติข้อมูลสินค้า และการเผยแพร่คำตอบจริง
- การเปลี่ยนกฎสินค้า สต็อก ชำระเงิน หรือสิทธิ์บัญชีที่ไม่จำเป็นต่อโครงหน้าจอ
- การคัดลอกเนื้อหา โปรโมชัน ภาพ หรือคำกล่าวอ้างของ Dr.PONG
