# แผนงานบัญชี คำสั่งซื้อ และการซื้อโดยไม่กรอกฟอร์มล็อกอิน

สถานะ: ระยะที่ 1 ทำแล้ว; ระยะที่ 2 กำลังปรับ flow Order/PromptPay บน branch `Login`. Firebase โปรเจกต์นี้ใช้ทดสอบ; ยังต้องยืนยันการตั้ง Omise secrets ใน Firebase Secret Manager และการเปิด PromptPay ก่อนทดสอบ QR จริง

แผนนี้เป็นงานถัดจาก [แผนโครงหน้าร้านจอคอมพิวเตอร์](./desktop-storefront-ticket-plan.md) และไม่เปลี่ยนสถานะของ 14 ตั๋วที่ทำไปแล้ว

## ขอบเขตที่ทำก่อน

ตามการตัดสินใจล่าสุด ให้ทำ **การเข้าสู่ระบบก่อน**: ใช้ Firebase Authentication ชุดเดียวสำหรับลูกค้าและผู้ดูแลระบบ ตรวจ role จริง เปิด `/account` และ `/account/profile` ตามสิทธิ์ และสลับหน้าร้าน/หลังบ้านโดยคง session รายละเอียดและเกณฑ์ทดสอบของระยะนี้อยู่ใน [สเปกเข้าสู่ระบบ](../.scratch/guest-checkout-and-account/spec.md)

**การซื้อขายเป็นระยะที่ 2**: ผู้มาเยือนดูสินค้าและใช้ตะกร้าได้โดยไม่ล็อกอิน; Order จะถือว่าบันทึกแล้วก็ต่อเมื่อ Cloud Function เขียนเอกสารลง Firestore สำเร็จ ไม่ใช่เมื่อกดปุ่มหรือเห็นป๊อปอัป

หัวข้อเส้นทางผู้ใช้ ข้อมูลคำสั่งซื้อ การชำระเงิน และเกณฑ์รับงานด้านการซื้อขายด้านล่างเป็น **แผนระยะที่ 2** ไม่ใช่สิ่งที่สเปกเข้าสู่ระบบระยะที่ 1 รับปากว่าจะส่งมอบ

## การตัดสินใจที่ยืนยันแล้ว

1. ลูกค้าสั่งซื้อได้โดยไม่กรอกฟอร์มล็อกอินหรือสมัครสมาชิกก่อนยืนยันคำสั่งซื้อ แต่ยังต้องกรอกข้อมูลติดต่อและการจัดส่งที่จำเป็น
2. ลูกค้าและผู้ดูแลระบบใช้ Firebase Authentication ชุดเดียวกัน สิทธิ์ `customer`, `admin` และ `super_admin` มาจากข้อมูลสิทธิ์จริง ไม่ได้มาจากปุ่มที่ผู้ใช้เลือกเอง
3. ปุ่มไปหลังบ้านแสดงเฉพาะบัญชีที่มีสิทธิ์ `admin` หรือ `super_admin` การกดปุ่มเปลี่ยนเส้นทางหน้าเว็บโดยคง session เดิม ไม่เปลี่ยน role และไม่ข้ามการตรวจสิทธิ์
4. หน้า `/account` เป็นภาพรวมบัญชี ส่วน `/account/profile` ใช้จัดการข้อมูลส่วนตัว หน้าล็อกอินยังมีไว้สำหรับบัญชีและผู้ซื้อที่ต้องการเข้าสู่ระบบ โดยไม่มีหน้าเกริ่นก่อนฟอร์มล็อกอิน
5. ระยะที่ 2 ทดลองเชื่อม PromptPay ผ่าน **Omise Test Mode** ก่อน และคิดค่าส่ง 30 บาทต่อ Order; secret key ต้องอยู่ใน Firebase Secret Manager ส่วน PromptPay ต้องเปิดใช้กับ Omise
6. Checkout ของ guest เก็บอีเมลที่ผู้ซื้อกรอกเป็นข้อมูลติดต่อในคำสั่งซื้อ และแสดงป๊อปอัปสาธิตหลังบันทึกคำสั่งซื้อ โดยระบุชัดว่า **ยังไม่ได้ส่งอีเมลจริง** ระยะนี้ไม่ทำการส่งเมล การค้นคำสั่งซื้อข้ามเครื่องด้วยอีเมล หรือการผูกคำสั่งซื้อ guest เข้าบัญชีภายหลัง
7. บันทึก Order สถานะ `pending_payment` ก่อนเริ่ม PromptPay; ปัญหาการตั้งค่า/เรียก Omise ต้องไม่ลบ Order ที่บันทึกแล้ว
8. Order จองสต็อก 30 นาทีจากเวลาสร้าง; ไม่ใช้ Scheduled Function จึงตรวจหมดอายุและคืนสต็อกเมื่อมีการเรียกอ่าน Order เริ่มจ่าย หรือสร้าง checkout ใหม่ ซึ่งอาจช้ากว่า 30 นาทีหากไม่มีคำขอเข้า

## ภาพรวมเส้นทางผู้ใช้

- **ผู้มาเยือน:** เลือกสินค้า → ตะกร้า → checkout → กรอกข้อมูลติดต่อ/จัดส่ง → ตรวจทาน → ยืนยันคำสั่งซื้อ → ได้เลขคำสั่งซื้อและหน้าสถานะ โดยไม่ผ่านฟอร์มล็อกอิน
- **ลูกค้าที่เข้าสู่ระบบ:** ใช้ checkout เดียวกัน คำสั่งซื้อผูกกับ UID ของบัญชี และดูย้อนหลังที่ `/account/orders`
- **ผู้ดูแลระบบ:** ใช้บัญชีเดียวกับหน้าร้าน เมื่อ role อนุญาตจะเห็นทางเข้าหลังบ้าน และอ่านคำสั่งซื้อทั้งหมดเพื่อจัดการและทำ dashboard
- **ผู้ซื้อแบบ guest ที่สมัครภายหลัง:** คำสั่งซื้อเดิมยังไม่เชื่อมเข้าบัญชีโดยอัตโนมัติ อีเมลที่กรอกใน checkout เป็นข้อมูลติดต่อ ไม่ใช่หลักฐานว่าเจ้าของบัญชีเป็นผู้สั่งซื้อ

## แผนข้อมูลและสิทธิ์

1. เก็บคำสั่งซื้อทุกประเภทในแหล่งข้อมูลส่วนกลาง เช่น `orders/{orderId}` โดยบันทึกเลขคำสั่งซื้อ สถานะ เวลา รายการสินค้าและราคาที่ซื้อจริง ยอดรวม ข้อมูลจัดส่ง อีเมลและช่องทางติดต่อที่ guest กรอก รวมถึง UID ของบัญชีหรือ identity ชั่วคราวเมื่อมี คำสั่งซื้อไม่หายเมื่อผู้ซื้อปิดหน้าเว็บ
2. ใช้ identity ชั่วคราวสำหรับ guest ผ่าน Firebase Anonymous Authentication เป็นแนวทางตั้งต้น เพราะสามารถเชื่อมกับบัญชีถาวรโดยคง UID เดิมได้ ทางเลือกนี้ต้องแยก anonymous user ออกจากบัญชีที่สมัครแล้วใน UI และกฎสิทธิ์
3. สร้างคำสั่งซื้อผ่านส่วนที่เชื่อถือได้ซึ่งตรวจราคา สต็อก ค่าจัดส่ง และยอดรวมจากข้อมูลร้าน ณ เวลายืนยัน ไม่รับยอดรวม สถานะชำระเงิน หรือ role ที่ส่งมาจากหน้าเว็บเป็นความจริงโดยตรง ป้องกันการสร้างคำสั่งซื้อซ้ำเมื่อกดซ้ำหรือเครือข่ายขาดช่วง
4. กำหนด Firestore Security Rules ให้เจ้าของคำสั่งซื้ออ่านได้เฉพาะของตน ผู้ดูแลระบบอ่าน/จัดการได้ตาม role และห้ามลูกค้าแก้ยอดหรือสถานะเอง หน้า dashboard ดึงจากคำสั่งซื้อส่วนกลางเดียวกัน ไม่ต้องพึ่งว่าผู้ซื้อสมัครสมาชิกหรือไม่
5. ระยะนี้ guest ดูคำสั่งซื้อได้เฉพาะผ่านตัวตนชั่วคราวที่ยังมีสิทธิ์เข้าถึง หรือข้อมูลที่แสดงทันทีหลังสร้างคำสั่งซื้อ ไม่เปิดการค้นหรืออ่านคำสั่งซื้อข้ามเครื่องด้วยอีเมลหรือเลขคำสั่งซื้ออย่างเดียว ป๊อปอัปสาธิตไม่ถือว่าได้ยืนยันตัวตน
6. การจ่ายเงินผ่าน Omise Test Mode ต้องสร้างคำขอผ่านฝั่งเซิร์ฟเวอร์โดยเก็บ secret key นอกหน้าเว็บ รับ token/source จากช่องทางที่ Omise รองรับ และตรวจสถานะ charge จาก Omise ก่อนปรับสถานะคำสั่งซื้อ การกลับจากหน้าจ่ายเงินหรือการแสดงป๊อปอัปอย่างเดียวไม่ถือว่าชำระสำเร็จ
7. ตรวจสอบกฎที่มีอยู่ก่อนใช้งานจริง: `firestore.rules` ยังไม่มี `orders`; `storage.rules` อนุญาตผู้ล็อกอินทุกคนเขียนรูปสินค้า ต้องกำหนดสิทธิ์ตาม role ให้ตรงกัน

## ลำดับงานระยะที่ 2: คำสั่งซื้อและ guest checkout

1. กำหนดรูปแบบคำสั่งซื้อและสถานะ กำหนดค่าจัดส่งช่วงทดลอง 30 บาทต่อคำสั่งซื้อ และใช้ PromptPay ผ่าน Omise Test Mode พร้อมตรวจผลจาก charge และ webhook
2. เตรียม Firebase Emulator สำหรับ Auth, Firestore และ Storage และบัญชีทดสอบ role ต่าง ๆ เพื่อทดสอบโดยไม่ใช้ข้อมูลจริง
3. สร้างการบันทึกคำสั่งซื้อที่เชื่อถือได้และกฎสิทธิ์ แล้วเชื่อม checkout กับหน้าผลสั่งซื้อสำเร็จ
4. เชื่อมประวัติคำสั่งซื้อของบัญชีและข้อมูลคำสั่งซื้อในหลังบ้าน/dashboard; เก็บอีเมลติดต่อของ guest และทำป๊อปอัปสาธิตโดยไม่อ้างว่าส่งเมลจริง
5. เชื่อมหน้า login และ account ที่ทำในระยะที่ 1 เข้ากับคำสั่งซื้อจริง โดยคงการตรวจ role และการป้องกัน route/ข้อมูลฝั่ง Firebase
6. ทดสอบเส้นทาง guest, ลูกค้าที่ล็อกอิน, admin และผู้ไม่มีสิทธิ์ รวมถึงการซื้อซ้ำ การสูญเสีย session และการเข้าถึงคำสั่งซื้อของผู้อื่น

### แยกงานตามความพร้อมของ Omise

- **การบันทึก Order:** server parameter `CHECKOUT_MODE=test` เปิดให้โปรเจกต์ทดสอบบันทึก Order รอชำระได้; ค่าเริ่มต้น `disabled` ป้องกันโปรเจกต์อื่นรับ Order โดยไม่พร้อมชำระ
- หน้าเว็บใช้ `VITE_CHECKOUT_TEST_MODE_ENABLED` แสดงปุ่มบันทึก Order ทดสอบก่อนตั้งค่า Omise; สิทธิ์รับ Order จริงยังตรวจ `CHECKOUT_MODE=test` ที่ Cloud Functions
- **การชำระ PromptPay:** `startPromptPay` ต้องใช้ทั้ง Test Mode secret และ webhook secret จาก Firebase Secret Manager; ถ้ายังขาดอย่างใดอย่างหนึ่ง ให้คง Order ไว้และแสดงทางลองเริ่มจ่ายใหม่
- Order หมดอายุหลัง 30 นาที; การคืนสต็อกต้องตรวจ charge กับ Omise ก่อนเมื่อมี attempt ที่อาจสร้าง charge แล้ว และตั้ง `ref_id` คงที่เพื่อไม่สร้าง charge ซ้ำจากคำขอที่ผลไม่ชัด
- ป๊อปอัปสาธิตอีเมลเป็นงานแยกจากการชำระเงิน ไม่ส่งเมลจริง และไม่ใช้แทนการยืนยันตัวตน

## เกณฑ์รับงานระยะที่ 2

- ผู้ไม่ได้ล็อกอินสั่งซื้อได้จริงและได้รับเลขคำสั่งซื้อที่บันทึกถาวร
- ผู้ล็อกอินเห็นเฉพาะคำสั่งซื้อของตนในบัญชี; admin เห็นคำสั่งซื้อทั้งจาก guest และบัญชีใน dashboard
- คำสั่งซื้อ guest เก็บอีเมลที่กรอกเป็นข้อมูลติดต่อ; ป๊อปอัปสาธิตต้องบอกว่าไม่ได้ส่งอีเมลจริง และอีเมลหรือเลขคำสั่งซื้อเพียงอย่างเดียวไม่เปิดเผยข้อมูลคำสั่งซื้อจากเครื่องอื่น
- การแก้ role ในหน้าเว็บหรือเรียก Firestore โดยตรงไม่ทำให้ผู้ไม่มีสิทธิ์อ่าน/แก้ข้อมูลหลังบ้านได้
- ปุ่มสลับหน้าร้าน/หลังบ้านปรากฏเฉพาะผู้มี role ที่อนุญาต และการสลับไม่ต้องล็อกอินซ้ำ
- ระบบไม่แสดงว่าสั่งซื้อหรือชำระเงินสำเร็จจนกว่าจะบันทึกคำสั่งซื้อและตรวจสถานะที่เกี่ยวข้องสำเร็จ; การชำระผ่าน Omise ในช่วงทดลองใช้ Test Mode เท่านั้น
- หากยังไม่มี Omise secret ระบบทดสอบยังบันทึก Order ได้ แต่เริ่ม PromptPay ไม่ได้และต้องไม่แสดงว่าชำระแล้ว; live checkout ต้องไม่เปิดด้วย flag ฝั่งหน้าเว็บเพียงอย่างเดียว
- Order ที่พ้น 30 นาทีและถูกประมวลผลเมื่อมี API activity คืนสต็อกเพียงครั้งเดียว; Order ที่มีผล Omise ไม่ชัดต้องตรวจสอบก่อนคืนสต็อก

## การตั้งค่าก่อนทดสอบ PromptPay

- ตั้ง `CHECKOUT_MODE=test` ในไฟล์ Functions เฉพาะโปรเจกต์ทดสอบ และตั้ง `OMISE_SECRET_KEY` กับ `OMISE_WEBHOOK_SECRET` ใน Firebase Secret Manager; ทั้งสอง secret ต้องพร้อมก่อนเริ่มสร้าง QR
- เปิด PromptPay ในบัญชี Omise Test Mode และลงทะเบียน webhook URL หลัง deploy Functions
- การมี secret ใน `.env` ของเว็บไม่ทำให้ Cloud Functions อ่าน secret นั้นได้
